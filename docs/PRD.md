# PRD — 校园值班管理

## 产品目标
用数字化工具替代纸质值班表与口头调班，实现「排班 → 履职（打卡）→ 监督（巡查）→ 变更（调班）」全链路管理，
并作为校园信息化大屏的值班数据源。

## 用户与使用场景
| 用户 | 角色 | 典型场景 |
|------|------|----------|
| 教师 | teacher | 手机上查看今日执勤任务 → 到岗拍照打卡；有事时发起调班 |
| 领导（授权教师） | teacher + canInspect | 在岗巡查，抽样核对各地点教师是否在岗 |
| 值班管理员/行政 | admin | 配置区域/地点/时段、维护排班模板、Excel 导入、审批调班、查看到岗率 |
| 访客/校领导 | guest（大屏） | 查看今日到岗率与值班矩阵 |

## 核心问题
1. 教师值班排班靠 Excel「一张总表」，维护成本高、易错
2. 到岗无记录、执勤无凭证
3. 临时调班靠口头、无审批留痕、无叠加追溯
4. 领导巡查在岗无抽样工具
5. 到岗率手工统计费时易错

## 功能及其意义
| 功能 | 解决什么 | 为什么需要 |
|------|----------|------------|
| 区域 / 地点 / 时段配置 | 执勤岗位可配置 | 各校岗位设置不同（校门口 / 教学楼 / 操场…） |
| 排班模板（周期 + 单双周 + 会签） | 一条模板描述整学期周期执勤 | 排班是周期性的，逐日录入不现实 |
| Excel 排班导入 | 从现有排班表一键导入 | 对接学校既有习惯，降低迁移成本 |
| 值班大表矩阵 | 地点 × 一周 7 天实时矩阵 | 排班全景一目了然，状态永不漂移 |
| 执勤打卡（照片必填） | 到岗凭证 | 有凭证才能监督、可回溯 |
| 本人班次守卫 | 防越权代打卡 | 打卡必须由实际值班人本人完成 |
| 领导巡查 | 抽样核对在岗 | 自上而下的履职核查 |
| 调班申请与审批 | 交换 / 代理，审批后叠加生效 | 临时变更需受控、可审计 |
| 到岗率统计 | 应到 / 实到，精确到人 | 值班质量的量化指标 |
| 多校区管理 | 多校区数据隔离 | 各校区独立运行互不干扰 |
| 数字大屏数据源 | 校园信息化展示 | 值班到岗率同框展示 |

## 功能之间的关系
```
配置(区域/地点/时段) → 排班模板(周期) ─(实时展开)─> 值班大表矩阵
                                              ├── 执勤打卡(照片) → 到岗率统计
                                              ├── 领导巡查(抽样核对在岗)
                                              └── 调班审批 → 叠加层(实时改变实际值班人)
```

## 核心设计原则
- **状态不持久化、实时计算**：DB 只存周期模板 + 打卡 + 已批准调班；展开实例、矩阵、到岗率均在查询时由纯函数引擎实时算出。
- **调班 = 叠加层**：审批通过不回改原排班模板，而是叠加一层「实际值班人」映射，按具体日期命中，天然可追溯、可回滚。
- **四层同构**：排班 → 履职 → 监督 → 变更。

## 范围与非目标
- **范围内**：教师执勤排班、打卡（照片）、领导巡查、调班审批、值班大表矩阵、到岗率统计、Excel 导入、多校区隔离、大屏数据源
- **范围外**：对接真实短信 / 邮件推送通道、学生请假管理、课表系统；值周生班级打分（属 `guga-onduty-w`）
