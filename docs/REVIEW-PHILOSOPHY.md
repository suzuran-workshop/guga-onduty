## 0. 统一哲学：巡查职责的四层同构

值班域是「巡查业务」的**粗粒度**实现，形式化为四层：

```
排班(Schedule) → 履职(Performance) → 监督(Oversight) → 变更(Workflow)
   谁·何时·何地      到岗并留下记录        上级核查在岗       受控临时变更
```

| 层 | 值班域实现 |
|----|-----------|
| 排班 | `dutySchedules`（周期模板）→ 实时展开为 `DutyInstance` |
| 履职 | `dutyCheckins`（到岗打卡 + 照片必填，精确到人） |
| 监督 | `dutyInspections`（领导抽样查在岗 / 不在岗） |
| 变更 | `dutySwaps`（交换 / 代理，审批后叠加层生效，不回改原排班） |
| 展示 | 值班大表矩阵（地点 × 一周 7 天，pill 三态） |

## 2. 值班域对抗性审查结果（新鲜怀疑视角）

先保正确性（bug > 哲学）。复查值班域 9 文件，报 **19 项、13 项确认**。
按严重度处置如下（✅ 已修 + 回归测试 / ⏸️ 已论证 deferred）：

| # | 级别 | 缺陷 | 处置 |
|---|------|------|------|
| 1 | P1 | POST /swaps 注释称校验本人值班、代码只查 campusId 未查 assigneeIds → 教师可挪他人班次 | ✅ 抽 `resolveDutyGuard` 共享守卫（展开+叠加→实际值班人），打卡/调班同源复用 |
| 2 | P1 | matrix swapped 按**实例**判定 → 会签格一人换班整格标 swapped，抹掉同事打卡 | ✅ 改按**人**判定（originalIds 排除接手人） |
| 3 | P1 | 8 个配置 PUT/DELETE 无 campusId 归属校验 + DELETE 不存在静默 200 | ✅ 统一 `assertEntityOwnership`（消除 5× 重复） |
| 4 | P2 | 单双周锚点用「各排班自身 dateStart」→ 两条 odd 排班 dateStart 不同则错位 | ✅ 校区级 parityAnchor（`settings.semester_start`），矩阵/打卡/到岗率/守卫四处同源 |
| 5 | P2 | `excelSerialToDate` 用本地 getter → 西区时区 off-by-one | ✅ 改 UTC getter（现代日期恒定） |
| 6 | P2 | Excel 同名地点跨区域合并 | ✅ 改 `(areaId\|name)` 区域限定键 |
| 7 | P2 | 非法日期 query 静默返回空 200 | ✅ `assertDateParam` 端点显式 400 |
| 10 | P2 | 重名教师导入静默取最后一个 | ✅ 检测 dupNames 并告警提示人工核对 |
| 12 | P2 | 配置删除无引用守卫 → 悬挂外键 | ✅ 区域/地点/时段删除前查引用，被引用则 409 |
| 13 | P3 | 巡查照片 `=` 覆盖而非追加 | ✅ 改追加 |
| 8 | P2 | `listApproved` 无日期界限，每次全量加载历史调班 | ⏸️ deferred：校内规模（百级/学期）overlay O(1) 键足够 |
| 9 | P2 | 导入配置预建与 bulkCreate 非同事务 | ⏸️ deferred：残留空壳配置可重导复用（幂等），低危 |
| 11 | P2 | 教师调班列表 pageSize:100 后 JS 切片，超 100 静默截断 | ⏸️ deferred：一学期调班量远低于 100 |

**审查同时确认无误的关键实现**：
- POST /checkins 本人守卫**先叠加调班再判实际值班人**——接手人能打卡、被换下的人不能，是全文件最对的授权校验。
- checkin-index 精确到人（scheduleId+date+teacherId），会签 A 打卡不污染 B。
- expand 日期算术（startOfDay 归一、setDate 本地推进、双向裁剪、DST）无 off-by-one。
- swap-overlay 代理无残留、Set 去重防会签重复、同 key 多调班共存、createdAt 升序「后者覆盖」。
- repo 读路径全部带 campusId；bulkCreate/review 事务原子；swaps.review 的 `WHERE status='pending'` 防重复审批。

**回归**：每项修复配 `duty-review.test.ts` 断言（现 20 项），全套 105 tests 绿（值班拆分后）。

## 3. 拆分相关的改良说明（原融合改良，已随拆分调整）

| 编号 | 原改良（合一仓库时期） | 拆分后归属 |
|------|----------------------|-----------|
| **A** | 到岗率桥接值周履职（`dutyWeek` 排班日提交 `records` = 到岗） | ❌ **已随拆分移除**——值周域迁出，本仓库到岗率只认 `dutyCheckins`；`DutyKind` 收敛为 `teaching` |
| **B** | 大屏 / 看板增值班维度（到岗率 + 矩阵缩略 + 打卡流） | 值班大屏数据源由本仓库提供；大屏页面本身在值周仓库（合并展示场景暂不含） |

| **C** | 文档澄清「监督层双维度」 | ✅ 本文 §0 的监督层（巡查自上而下） |

> **拆分原则复核**：值为「分层统一」——排班层合一、度量层桥接、展示层并陈、履职形状各自保留。
> 拆分把「合一」还原为「两个独立产品」，值班域因此回到**自洽的单一度量**（到岗率仅度量教师执勤打卡）。

## 4. 值周审查后的剩余改良（两域共用，已在本仓库保留）

- **bodyLimit**：图片上传 9×5MB 全量进内存、无请求体上限 → 全局 `bodyLimit(50MB)` 中间件防 DoS。
- **users.remove 原子性**：先删 auth 身份锚点再删 profile，避免「profile 删了但 auth user 删失败 → 账号变砖（永久 403）」；
  失败则整体抛错、profile 保留（不 brick），并释放 username。

## 5. 核心教训（跨域通用）

**状态断言通过 ≠ 语义正确**：测试若只断言「状态迁移」（如 approve 后 status 变 X），会漏掉「业务效果」错误。
必须补两类测试：① **业务效果的数值断言**（如到岗率、分数变化）；② **同角色跨主体越权**（A 校区动 B 校区、教师挪他人班次）——
happy-path + 角色维度测试测不出这些。本仓库 `duty-review.test.ts` 即为补齐此类盲区而建。
